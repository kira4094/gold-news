# 新闻汇总技能

当用户需要汇总新闻时，主动搜索网络获取最新信息，按国际/国内分类呈现。

---

## 模式选择

根据用户请求自动匹配合适模式：

| 用户意图 | 模式 | 日期范围 | 搜索策略 |
|---------|------|---------|---------|
| "今天新闻""今日要闻" | `today` | 当天 | 重点搜今日，精确匹配 |
| "最近几天""这几天" | `multi-day` | 近 2-3 天 | 分批搜索每日，覆盖全 |
| "本周新闻""这周" | `weekly` | 近 7 天 | 按周搜索+每日补搜 |
| "XX领域新闻"（科技/体育/经济） | `domain` | 近 2 天 | 领域关键词+通用词交叉 |
| "帮我看看XX"（具体事件） | `specific` | 按事件时间 | 精准搜索+多角度验证 |

**边界：** 若用户意图模糊（只说"有什么新闻"），默认 `today` 模式。

---

## 工作流程

### Phase 0: 意图匹配（入口）

```
用户请求 → 匹配模式选择表：
├─ 命中明确模式（today/multi-day/weekly/domain/specific）→ 走对应模式
├─ 意图模糊（只说"有什么新闻""最近有啥事"）→ 默认 today 模式
└─ 不匹配触发词（非新闻请求）→ 中止新闻流程，切回常规模式
```

### Phase A: 搜索策略

**🔴 CHECKPOINT：** 搜索前，若用户未指定具体兴趣方向，先问一句「有特别关注的领域或地区吗？」。如果用户说"随便"或"不用"，直接执行默认搜索。

#### A1. 确定日期

- 使用当前会话日期（用户提问当天）作为基准
- `today` 模式：当天
- `multi-day` 模式：当天 + 前 2 天
- `weekly` 模式：当天 + 前 7 天
- 注意时区：如果用户本地时间和系统时间可能不一致，以用户语境为准

#### A2. 构建搜索词

根据模式和上下文，从以下模板中选择 2-3 个搜索词，保证覆盖广度和精度：

**通用搜索（必选至少 1 个）：**
- `"最新新闻 今日要闻 {月/日}"` — 国内综合
- `"latest breaking news today {month} {day}"` — 国际综合
- `"world news headlines today"` — 国际综合备选

**按模式补充：**
- `multi-day` → 追加 `"{月/日} 新闻汇总"`、`"{previous_day} news roundup"`
- `weekly` → 追加 `"this week top stories"`、`"本周热点新闻"`
- `domain` → 追加 `"{领域} 新闻 {日期}"`、`"{domain} news {date}"`

**按用户兴趣补充：**
- 用户提到地区 → 追加 `"{地区} 新闻"`、`"{region} news"`
- 用户提到事件 → 追加 `"{事件关键词}"`

#### A3. 执行搜索

```
1. 先用 2 个最相关的搜索词并行搜索（WebSearch）
2. 评估搜索结果质量：
   - 若结果数 > 10 条有效新闻 → 继续 Phase B
   - 若结果数 < 5 条 → 用备选搜索词再搜一轮
   - 若两轮都搜不到足够结果 → 拓宽搜索词（去掉日期、换更通用的词）
3. 记录实际使用的搜索词（用于问题排查）
```

**异常处理（内联）：**
| 触发条件 | 一线修复 | 仍失败兜底 |
|:---------|:---------|:-----------|
| WebSearch 返回空或报错 | 换一个搜索词重试，最多 2 次 | 明确告知"当前新闻搜索不可用" |
| 搜索到重复内容 | Phase B 去重，保留权威/完整的那条 | 全部重复时标注"搜索结果有限" |
| 单来源垄断（全部来自同一网站） | 追加不同来源的搜索词 | 仍垄断时提示用户"结果来源单一，仅供参考" |

#### A4. 用户自定义内容

如果用户直接在消息中提供了新闻内容或链接：
- 链接 → 使用 WebFetch 获取内容后提取新闻
- 文本 → 直接作为新闻源整理
- 用户内容优先于搜索内容

**🔴 CHECKPOINT：搜索结果质量是否合格？**
- 有效新闻 > 10 条 → 继续 Phase B
- 有效新闻 5-10 条 → 直接继续，输出时备注"搜索结果有限"
- 有效新闻 < 5 条 → 返回 A2 换搜索词重搜

---

### Phase B: 筛选与分类

#### B1. 去重与过滤

- 去除标题相似度高的重复新闻（保留来源更权威的一条）
- 去除明显过时的新闻（非指定日期范围）
- 去除广告/推广性质的内容

#### B2. 分类规则

将新闻分为两类：

- **国际新闻**：发生在国外的事件、国际关系、全球性议题
- **国内新闻**：发生在中国境内的事件、国内政策、民生新闻

分类原则：
- 中国外交、中国对国际事件的回应 → **国内新闻**（因为立场/视角是国内）
- 纯国外事件（如美国大选、欧洲能源危机）→ **国际新闻**
- 如果某条新闻兼具国际国内属性，根据主要视角决定分类

#### B3. 排序

每个类别内部按以下优先级排序：
1. 时效性（最新在前）
2. 重要性（头版头条级别优先）
3. 与用户兴趣的相关性（如用户提到了某领域）

---

### Phase C: 格式化输出

**🛑 STOP：确认是否有足够可用新闻**
- 搜索结果 > 10 条 → 直接输出完整版
- 搜索结果 < 5 条 → 问用户「是否放宽日期范围再搜？」
- 全失败 → 告知用户「新闻搜索暂不可用」

#### C0. 黄金日报硬联动（🔴 每次新闻汇总必做，不可省略）

**规则：用户说"新闻汇总"（或任何触发词）时，只要本次汇总涉及黄金/经济/地缘/美债任一维度，必须连带生成黄金日报，二合一输出。**

```
触发链：
用户说"新闻汇总"
→ 执行新闻多维度搜索（下方 C0.1 强制清单）
→ 若命中 黄金/经济/地缘/美债 任一维度
→ 必须调用 gold-price skill 的日报模板
→ 输出 = 新闻汇总 + 黄金日报（二合一）
```

**黄金日报模板：完整骨架见 `../gold-price/output-templates.md`**（gold-price × news-summary 共用）。4 项必备：① 当前金价 ② 持仓快照 ③ 本周关键数据 ④ 外网重磅，含**数据失效护栏**——拉不到数据须明说不报、禁估算填充，详见 gold-price/SKILL.md「新闻汇总联动」节与 `output-templates.md` 第一节。**本文件不再重复维护模板细节，防止两处漂移。**

> ⚠️ **若用户只说"新闻汇总"，黄金日报仍必须生成**——不要等用户单独说"黄金日报"。

#### C0.1 新闻多维度强制检查清单（🔴 每次汇总必过）

**汇总完整性硬要求：以下 6 个维度，漏掉任一项 = 汇总不完整，必须补搜。**（2026-08-25 用户指出漏"特朗普军事威胁债市""$950亿回购"后新增）

| 维度 | 强制项（必须检查） |
|:-----|:------------------|
| 🌍 **地缘政治** | 美伊/霍尔木兹/中东/俄乌/台海/中美 |
| 🏦 **美债/美联储** | 贝森特回购/收益率/特朗普涉债言论/沃什 |
| 🥇 **黄金/贵金属** | 金价/持仓/央行购金/金ETF |
| 🤖 **AI/科技** | 英伟达/芯片/OpenAI/数据中心/AI融资 |
| 📈 **市场** | 美股/比特币/大宗/A股/港股 |
| 🇨🇳 **国内** | 政策/产业/监管/民生 |

**检查流程：**
```
1. 每维度搜索 ≥1 个源
2. 若某维度当天无重大新闻 → 在输出中标注"（今日无重大XX新闻）"
3. 若发现未覆盖的重大信号（如总统涉金融言论）→ 补搜该关键词
4. 漏项 = 汇总不完整 → 返回 Phase A 补搜
```

**黄金日报和新闻汇总的关系：**
- 新闻汇总负责 6 维度全覆盖（C0.1）
- 黄金日报负责 4 项必备（C0）→ 由 gold-price skill 提供
- 两者**必须同时输出**，不能只给一个

#### C1. 输出格式

**完整可复制骨架（含二合一）见 `../gold-price/output-templates.md`**。ALWAYS 使用以下 markdown 格式：

> ⭐ 二合一（新闻汇总 + 黄金日报）→ 用 output-templates.md 模板四
> ⭐ 单独新闻汇总 → 用 output-templates.md 模板三
> ⭐ 仅金价快报 → 用 output-templates.md 模板六

```markdown
## 📋 新闻汇总 — YYYY年MM月DD日

### 🌍 国际新闻
1. **[标题]** — 一句话摘要（来源）
2. **[标题]** — 一句话摘要（来源）

### 🇨🇳 国内新闻
1. **[标题]** — 一句话摘要（来源）
2. **[标题]** — 一句话摘要（来源）
```

**输出规范：**
- 每条新闻包含：**标题**（加粗）、一句话摘要、来源（网站名）
- 国际和国内各输出 **5-8 条**，优先展示最重要、最新的新闻
- 保持摘要简洁，每条控制在 30 字以内
- 来源标注在摘要后的括号中，如（来源：新华社）
- 如果某个类别当天没有找到合适的新闻，保留分类标题并注明"暂无重要新闻"
- 如果用户要求的新闻涉及特定日期，在标题中标明日期

#### C2. 用户确认（可选）

如果搜索到的重要新闻较少（< 5 条），或者来自不可靠来源（如自媒体、未核实渠道），在输出结尾加一行备注：

> ⚠️ 部分新闻来源未经官方核实，建议进一步确认。

## 反例与黑名单

| # | ❌ 不要这样做 | 为什么 | ✅ 应该这样做 |
|:-:|:-------------|:-------|:-------------|
| 1 | **把新闻汇总当万能搜索** | 用户问"查找XX资料"非新闻需求，执行新闻流程浪费时间 | 先判断意图是否匹配触发词，不匹配 → 切常规模式 |
| 2 | **中国回应国际事件归为国际新闻** | 中国外交部表态、中国对外事件的回应，视角是中国立场 | 中国外交/回应 → **国内新闻**（按立场视角分类） |
| 3 | **直接信来源不验证** | 自媒体/未核实渠道可能传播假新闻 | 可疑来源跳过，多条可疑时整体标注「部分来源未核实」 |
| 4 | **放行广告/推广内容** | 搜索结果混入软文，影响新闻质量 | Phase B 去重过滤阶段必去掉商业推广内容 |
| 5 | **日期硬编码不过期** | 写死日期（如 `2026-05-25`）导致引用永远错误 | 用当前会话日期，动态生成搜索词 |
| 6 | **搜索结果不足仍硬出** | < 3 条可用新闻时强行输出，用户看到零星内容 | 先问用户「是否放宽日期范围？」再决定 |
| 7 | **所有输出都用同一模板** | 领域新闻（如"科技新闻"）和综合新闻应有区分 | 按模式选模板：综合→国际/国内分类；领域→按领域分类 |

## 🛟 异常与 Fallback

| 触发条件 | 一线修复 | 仍失败兜底 |
|:---------|:---------|:-----------|
| WebSearch 全部失败 | 换搜索词重试 1 次 | 告知「新闻搜索暂不可用」，建议用户自行提供来源 |
| 搜索结果不足（< 3 条每类） | 放宽日期范围再搜 1 次 | 如实说明，问用户「是否继续？」 |
| 用户提供链接但打不开 | 用 WebFetch 重试 1 次 | 提示「链接无法获取」，请用户提供文本 |
| 非新闻类请求误触发 | 检查用户 intent 是否匹配触发词列表 | 中止新闻流程，切回常规模式 |
| 搜索结果全是同一来源 | 追加不同来源搜索词再搜 | 仍单一时提示「来源单一，仅供参考」 |
| 用户处于非中文环境 | 优先搜索当地语言新闻 | 翻译为中文整理输出 |
| 搜索结果包含明显假新闻/谣言 | 跳过该条，不纳入输出 | 多条可疑时整体标注「部分来源未核实」 |
